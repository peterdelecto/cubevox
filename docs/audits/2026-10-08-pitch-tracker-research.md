# Panes flatten the YIN burst to two percent

**BLUF.** The 31 %/45 % tracker burst can be removed rather than trimmed, without touching the gates or the 1040-sample latency, by exploiting the fact that the coarse window (W = 256 decimated samples) is exactly 16 audio blocks and the hop exactly 4: every term of d(τ) that the hop-boundary pick needs is computable from samples that have already arrived, so the difference function can be accumulated as 16 block-aligned partial sums ("panes"), one new pane of 171 × 16 = 2,736 MACs per block, with nothing left at the hop boundary but 2,565 adds, the CMND and the pick. This is the same window, the same statistic and the same alignment as today (summation order differs, so it lands on the −60 dB `engine_ab` floor, not −200), it has no eviction subtraction and therefore no float drift, and it costs half the MACs per hop of Hildebrand's recursive E/H update while needing no rebase. Applied with a predicted-lag pipelining of the 48 kHz fine pass (25 lags × 64 = 1.6k MACs per block, with the present 9-lag 9.2k-MAC search kept only as a fallback on pitch jumps), the steady-state tracker cost becomes ≈ 4.3k MACs every block ≈ 13k cycles ≈ **2.0 %** at the measured 3 cycles/MAC, and ≈ 1.2 % if the pane kernel is rewritten as a pure-VFMA autocorrelation (d = E₀ + E_τ − 2r) with 4 × 2 register blocking; the worst block (hop boundary plus fine fallback) is ≈ **7.7 %** instead of 45 % (all derived). The 45 %-versus-31 % spread is most plausibly memory placement and cache state (a 2.2× DTCM-versus-AXI penalty is measured on the H7, and the hop-boundary data-dependent branches can account for < 0.2 %), so DTCM/ITCM placement and a DWT CYCCNT min/max harness are the first, bit-identical steps. On the PSOLA side, each grain reads at a constant fractional delay, so Catmull-Rom collapses to four weights computed at launch: ≈ 20 → 7 ops per grain-sample, bit-exact candidate, ≈ 40 % of the grain loop; Praat's window rule L = 2·min(P, P/r) then caps live grains at two so the r → 2 worst case equals the r = 1 average, at a quality cost that must be auditioned rather than gated. Finally, the TDE literature identifies the three-point parabola as the most biased standard sub-sample interpolator; a 5-point or truncated-sinc fit on a fine search widened by one lag costs a few hundred ops per hop and is the one cheap trial that might move the 3.76-cent result.

### 1.1 Panes: the governing decomposition

The direct hop computation uses the newest W + τ_max decimated samples with j over the oldest W, so j ∈ [t_h − τ_max − W, t_h − τ_max) and x[j + τ] reaches at most t_h ([handoff](00_handoff_current_design.md)). Partition that j range into 16 panes of 16 decimated samples (one audio block each). Pane s needs samples up to (last j) + τ_max ≤ t_s, the end of block s, so it is computable in block s's ISR once the block has been written to the ring, and the pane ending at t_h − τ_max is computable in the hop block itself. Every pane the hop needs therefore exists at the hop boundary without touching samples that have not arrived, which is why pipelining adds no latency; the handoff's "spreading adds 5.3 ms" objection applies to *deferral* of a hop job, not to this data-availability split (the real-time-scheduling name for it is period transformation, Sha–Lehoczky–Rajkumar, cited from memory in the notes and unverified). Each pane is reused by the four consecutive hops whose windows contain it, so the per-hop MAC count is 43.8k/4 = 10.9k, half the 21.9k of the sliding update and four times below the burst. Storage is 16 × 171 floats = 10.9 KB; per-block working set is a 187-sample contiguous window (748 B) and one 171-float row, all DTCM-resident.

Numerically the panes form is *better* conditioned than the current loop: summation tree height is 16 inside a pane plus 15 across panes (h ≈ 31) versus ≈ 67 for the 4-accumulator direct sum, and the Hallman–Ipsen bound |e_n| ≤ u(1+u)^h Σ|s_k| scales with h ([Hallman & Ipsen](https://arxiv.org/pdf/2107.01604)). It is strictly preferable to subtract-on-evict because fp32 addition is not a group: an evicted term is subtracted with a rounding that no longer matches the one it was added with, so sliding sums drift (order √K·u·|d| after K updates) and must be rebased or made exact in int64, whereas every pane is a fresh finite sum. The sliding-window-aggregation literature makes the same distinction between invertible and non-invertible aggregates and shows constant-per-element cost needs only an associative operator, not an inverse ([Tangwongsan, Hirzel & Schneider](https://arxiv.org/pdf/2009.13768)). Under panes, early termination (rank 12) is moot because the pane must cover all 171 lags before the pick is known; the CMND and pick at the hop boundary are ≈ 1–2k ops regardless.

### 1.2 Fine pass: prediction with margin, fallback on jumps

The fine pass is pipelined the same way (panes of 64 full-rate samples over W = 1024, τ_max = 686, 750-sample window) provided the lag set is known one block ahead. The current centre T = round(4τ_c) comes from the same hop's coarse pass, which under pipelining is unknown until the boundary; instead predict T from the previous hop's newest period and widen the set to ±12 lags (25 lags, 1,600 MACs/block). If, at the boundary, the coarse T ± 4 lies inside the predicted set, the nine d values the current code would have used are all present and the pick and parabola are unchanged; if not, run today's direct 9-lag search as a fallback (9.2k MACs, in the hop block only). Vibrato stays inside the margin: at 5 Hz ±30 cents the per-hop drift is at most ≈ 2π·5·0.00533·30 ≈ 5 cents ≈ 0.3 % of the period, far below ±12 lags (≈ ±1.7 % even at P = 686), so only onsets and octave corrections trigger the fallback (derived, [alternative-trackers note](https://patents.google.com/patent/US5973252A/en) analysis of the Hildebrand window-shift rule). Hildebrand's correction mode is the published precedent: eight lags around the last period, window shifted by one when the minimum reaches an edge, full detection re-entered when the eps test fails, pitch changes too fast or energy drops ([US 5,973,252](https://patents.google.com/patent/US5973252A/en)); AMR's closed-loop search is likewise confined to "a small number of lags around the open-loop estimated lags" ([3GPP TS 26.090 §5.3](https://itecspec.com/3gpp/26.090/s/5.3)).

### 1.3 Kernel rewrites: VFMA-only and Q15

The measured ≈ 3 cycles/MAC is close to the floor for the difference form, not compiler slack: the M7 has a single FP pipe, VFMA.F32 sustains one per cycle only with ≥ 3 independent accumulators (a dependent chain runs at 3 cycles), and VFMA does not dual-issue with VLDR ([Arm community measurement](https://community.arm.com/support-forums/f/architectures-and-processors-forum/9930/cortex-m7-vfma-usage); [EEVblog, jnk0le](https://eevblog.com/forum/microcontrollers/cortex-m7-pipeline-idiosyncrasies/msg4503718); LLVM models the M7 as dual-issue with single-issue VLDM/VLDRD and effective FP latency 3, [ARMScheduleM7.td](https://src.rcs.uwaterloo.ca/xref/freebsd-src/contrib/llvm-project/llvm/lib/Target/ARM/ARMScheduleM7.td)). Each difference term costs VSUB + VFMA = 2 FP slots, so 2 cycles/MAC is the hard floor and more accumulators will not help. Rewriting d(τ) = E(0) + E(τ) − 2r(τ) removes the VSUB: the energies come from one prefix sum of x² shared by all lags, and the kernel is a pure cross-correlation at 1 FP op per MAC. With 4 j-values × 2 lags register-blocked (8 FMA + 6 VLDR per 8 MACs) the issue-slot model gives ≈ 1.75 cycles/MAC, ≈ 1.6 at 8 × 2; this is a model, not a measurement, and must be confirmed with DWT CYCCNT. The numerical cost is cancellation at the valley: d is formed as a small difference of two energies, so its relative rounding error is ≈ u·E/d ≈ u/d′ (u = 6e-8 for fp32), i.e. ≈ 6e-6 at d′ = 0.01 — far below what moves δ, but not bit-identical (derived). The 1.85× hand-asm-over-compiler figure in the EEVblog thread came from cross-iteration interleaving that `-funroll-all-loops` does not perform ([EEVblog page 1](https://www.eevblog.com/forum/microcontrollers/cortex-m7-pipeline-idiosyncrasies/)), so the inner pane kernel (≈ 20 instructions) should be hand-scheduled or at least checked in disassembly for VLDR-adjacent-to-VFMA pairs.

The Q15 path is the larger lever if the float kernel falls short: SMLAD does two 16-bit MACs per instruction at latency 2 and integer MACs co-issue with loads ([ARMScheduleM7.td](https://src.rcs.uwaterloo.ca/xref/freebsd-src/contrib/llvm-project/llvm/lib/Target/ARM/ARMScheduleM7.td); "load and store operations in parallel with arithmetic", [ST M7 training](https://www.st.com/content/ccc/resource/training/technical/product_training/group0/8d/11/c5/6d/be/15/4f/63/STM32H7-System-ARM_Cortex_M7_M7/files/STM32H7-System-ARM_Cortex_M7_M7.pdf/_jcr_content/translations/en.STM32H7-System-ARM_Cortex_M7_M7.pdf)); ST's only M7 fixed-point comparison shows a 1024-point Q15 FFT at 56,989 cycles against 93,725 for Q31 on an F746 ([AN4841](https://www.st.com/resource/en/application_note/dm00273990.pdf)). A 16-term pane of Q15 × Q15 products can reach 2^34, so accumulate with SMLALD (64-bit) rather than SMLAD, and convert the 171 pane sums with VCVT at the hop boundary; no measured M7 cycles/MAC for `arm_dot_prod_q15` were found, so the 0.5–1 cycle/MAC range is unverified. Because the coarse estimate only has to land within the fine window (±1 decimated lag) and the fine pass stays float, Q15 does not touch the 4-cent gate directly; the risk is the CMND division at small τ, which should remain in float on the converted sums.

### 1.4 PSOLA: constant-delay weights and the two-grain rule

Each grain "reads the ring at a constant delay (centre + P − lead)" ([handoff](00_handoff_current_design.md)), so the fraction f is fixed for the grain's lifetime and the Catmull-Rom read is a fixed 4-tap FIR whose weights (Section 6) cost ≈ 12 ops once per launch instead of ≈ 10 mul + 10 add per sample; Niemitalo's table gives 4-point Hermite (= Catmull-Rom) at 9 multiplies/19 ops in its cheapest per-sample form, which matches the handoff's structure ([Niemitalo 2001 §7](http://yehar.com/blog/wp-content/uploads/2009/08/deip.pdf)). Evaluating the same polynomial as four weights and summing in the same precision is a bit-exact candidate; if the compiler reassociates, expect the −60 dB class. The same trick makes an 8-tap windowed-sinc read cost 8 mul + 7 add, should a better kernel ever be wanted. Linear interpolation with constant fraction (2 weights, ≈ 3 ops) would also meet the pitch gate — output pitch is set by launch spacing, and Dattorro shows linear's fractional delay tracks the coefficient at low frequency with measured −78 to −88 dB THD+N on a slow vibrato ([Dattorro 1997 Part 2](https://ccrma.stanford.edu/~dattorro/EffectDesignPart2.pdf)) — but its HF tilt (−2 dB at 10 kHz, derived) is a quality change and is not recommended.

The r-dependence of the PSOLA cost is the live-grain count: with L = 2P and launches every P/r, ⌈2r⌉ (+1 transient) grains are alive, i.e. 2 at r = 1 and 4–5 at r = 2, so if the 5.6 % was measured near r = 1 the r = 2 worst case is ≈ 11 % per voice (derived). Praat's production TD-PSOLA bounds each window half-length by the minimum of the adjacent source and target periods ([Praat manual](https://www.fon.hum.uva.nl/praat/manual/overlap-add.html)), which for this engine is L = 2·min(P, P/r): for r ≥ 1 exactly two Hann grains overlap at 50 % and sum to one (the 1/r multiply can be dropped), for r < 1 the usual gaps remain. Bristow-Johnson's analysis frames Lent's method as interpolating between input spectral lines with the window transform as kernel and resampling at output harmonics ([AES paper 3718 abstract](https://aes2.org/publications/elibrary-page/?id=6514)), so shortening L broadens that kernel from ≈ ±f₀ to ≈ ±r·f₀ at r = 2 — smoothing, not shifting, the envelope. No listening test quantifies this; it is a quality decision, and because it changes the output at r > 1 well beyond −60 dB it needs a new AB reference rather than a gate pass.

**Recommended sequence**, each step gated by ctest hard-tune ≤ 4 cents RMS, pitch (vibrato ≤ 3 cents at every voiced hop, steady 220 Hz 0.04 cents, silence unvoiced, no allocation) and `engine_ab.sh` at the floor stated:

0. **Instrument** (no code change to the DSP): per-block DWT CYCCNT delta, classified into non-hop, hop and (later) fallback blocks, with min/max/histogram over ≥ 10⁴ blocks, logged alongside r and the live-grain count (Section 3).
1. **DTCM/ITCM placement** — expect −200 dB. If the WeAct default linker leaves `.bss` in AXI SRAM, this alone can take the hop block down by a large fraction and should narrow 45 % toward 31 %.
2. **PSOLA precomputed weights** and pool 8 → 6 — expect −200 dB (or −60 dB if the compiler reassociates). Per-voice ≈ 5.6 % → ≈ 3.5 %.
3. **Coarse panes in the difference form** (keep the VSUB so the terms are identical to today's and only the order changes) — expect −60 dB; ctest should be within noise of 3.76 cents. This is the step that removes the burst: hop block ≈ 31 % → ≈ 4.3 % fine + ≈ 2 % pane/combine.
4. **Predicted-lag fine panes with fallback** — expect −60 dB when prediction holds, identical on fallback; count fallback rate on the ctest and vibrato clips (should be near zero except at onsets). Steady state ≈ 2 %, worst ≈ 7.7 %.
5. **Pure-VFMA autocorrelation pane kernel**, hand-scheduled — expect −60 dB; measure cycles/MAC; target ≈ 1.2 % steady.
6. **Q15 SMLALD pane kernel** only if step 5 measures above ≈ 2 cycles/MAC — coarse only, −60 dB, re-run all pitch tests because the coarse statistic changes.
7. **Cosine-recursion window** (−60 dB) and, as a separate decision, the **Praat rule** with a listening test at r = 1.5–2 and a fresh AB reference.
8. **Interpolator trial** (Section 4) — an accuracy experiment on the fine pass, not a cost step.

Hildebrand's recursion is the right *alternative* to panes rather than a complement: both deliver a flat per-block cost on the same statistic, but panes use half the MACs per hop, need no rebase and keep fp32; the recursion wins only when the 10.9 KB pane array cannot be placed in DTCM, or as a per-sample DLL fine tracker once the design is already flat. FFT-YIN belongs in neither list (Section 5). Early termination is a cheap interim on the current direct code (bit-identical, average only) and disappears once panes are in.

## 3. Why the worst block is 45 % and how to prove it

The algorithmic work of the hop block is almost data-independent: the 171 × 256 and 9 × 1024 loops always run to completion, the pick loop and voiced/unvoiced branches are at most a few hundred data-dependent branches at 4–6 cycles per mispredict (LLVM models the forward-branch penalty as 6, "but 4 works better", [ARMScheduleM7.td](https://src.rcs.uwaterloo.ca/xref/freebsd-src/contrib/llvm-project/llvm/lib/Target/ARM/ARMScheduleM7.td)) — under 1k cycles, < 0.2 % of a block — and accumulator-chain stalls are static. A 14-point swing (≈ 90k cycles) must therefore come from the memory system, from preemption, or from PSOLA load coinciding with the hop block. The evidence favours memory: the same ITCM-resident assembly loop measured 154 µs with data in DTCM, 334 µs in AXI SRAM and 377 µs in flash with D-cache off ([ST community 71830](https://community.st.com/stm32-mcus-products-25/big-difference-in-execution-time-with-data-in-dtcm-axi-flash-71830)); a trivial loop ran 216,849 cycles from uncached AXI, 104,300 cached and 115,800 from DTCM regardless of cache ([ST community 5748](https://community.st.com/stm32-mcus-products-25/stm32h7-why-is-dcache-faster-than-dtcmram-5748)); a 4096-point float FFT on an H745 went from 1.6 s to 440 ms with caches on ([ST community 140218](https://community.st.com/stm32-mcus-products-25/time-delay-in-fft-performance-140218)); and code in flash makes interrupt latency "degrade from 38 ns to 67 ns randomly" at 480 MHz ([zff.dev](https://zff.dev/niconiconi/stm32h7-exti-latency)). The D-cache is 16 KB 4-way with 32-byte lines ([ST M7 training](https://www.st.com/content/ccc/resource/training/technical/product_training/group0/8d/11/c5/6d/be/15/4f/63/STM32H7-System-ARM_Cortex_M7_M7/files/STM32H7-System-ARM_Cortex_M7_M7.pdf/_jcr_content/translations/en.STM32H7-System-ARM_Cortex_M7_M7.pdf)), so a 10 KB ring pair plus other audio buffers is evicted between hops by UI, USB or other DSP whenever it lives in cached AXI; a hop whose rings are cold then pays the 2.2× penalty on a fraction of its accesses, and ≈ 30 % cold accesses reproduce a 31 → 45 % swing (derived). A second, additive contributor is PSOLA density: at r → 2 the grain loop carries 4–5 live grains instead of 2 (Section 1.4), so a hop block that coincides with a large upward correction carries ≈ +5 % per voice over the r = 1 figure (derived). Preemption by a USB or UI interrupt inside the burst is the third candidate; the Daisy community raises exactly this NVIC-priority concern for audio callbacks without an answer ([Daisy forum](https://community.daisy.audio/t/callback-priorities/4489)). Denormal-float penalties on the M7 FPU are undocumented in the sources found; setting FPSCR.FZ is a cheap guard but there is no measured penalty to attribute.

**Protocol.** Enable DEMCR bit 24, confirm DWT_CTRL reads non-zero, set bit 0, clear DWT_CYCCNT; take unsigned deltas per block (wrap-safe); because "repeated measurements of the same code may be inconsistent" with caches on, measure the worst case with D-cache disabled and the deadline case with caches and interrupts enabled, and keep the max over many runs for conditional code ([Embedded Computing Design](https://embeddedcomputing.com/technology/processing/measuring-code-execution-time-on-arm-cortex-m-mcus)). Classify each delta as non-hop, hop or fallback; record min, max and a coarse histogram per class over ≥ 10⁴ blocks; log r and the live-grain count with each sample so the PSOLA contribution separates from the tracker's; repeat with rings and tables in DTCM and the hop code in ITCM. If the hypothesis holds, the hop-block distribution collapses to a narrow band once data is in DTCM, and after panes the whole distribution collapses to two values (normal block, fallback block). For fully deterministic timing one M7 user reports disabling dynamic branch prediction and setting the undocumented DISFOLD bit (ACTLR = 0x04006004) plus ITCM execution and unrolling ([EEVblog, Siwastaja](https://eevblog.com/forum/microcontrollers/cortex-m7-pipeline-idiosyncrasies/msg4503718)); this costs average throughput and is a last resort, not a recommendation.

## 4. The parabola may be what limits 3.76 cents

Four cents is a relative period error of 2^(4/1200) − 1 = 0.231 %: 0.11 sample at P = 48 (1 kHz), 0.50 sample at P = 218 (220 Hz), 1.6 samples at P = 686 (derived). The fine pass resolves the period on a 48 kHz grid and hands the sub-sample part to the three-point parabola δ = ½(a − c)/(a − 2b + c). The time-delay-estimation literature is explicit that this is the most biased of the standard interpolators: the parabolic fit has "high estimation bias" that "depends on where the true delay falls within the sampling interval", the Gaussian fit is lower but "still susceptible to bias", and sinc/Whittaker–Shannon least-squares fits are lowest; measured at 8 kHz in a real room, median TDOA error was 7.56 µs parabolic, 3.97 µs Gaussian, 2.92 µs truncated sinc (S = 3) and 1.67 µs Whittaker–Shannon (S = 13), with the sinc family "robust at small window lengths, low sampling rates, and low SNR" ([Rosseel & van Waterschoot 2025](https://arxiv.org/pdf/2509.04629)). In sample units those are ≈ 0.06, 0.03, 0.023 and 0.013; if the parabolic figure carried over unchanged to 48 kHz samples it would be ≈ 2.2 cents at 1 kHz and ≈ 0.5 cent at 220 Hz — a material share of the budget exactly where the period is short, and a bias, so it does not average out in the 3-hop median or inside a DLL loop (derived; no source gives the bias for a YIN valley specifically).

Two cautions bound the expectation. First, for a band-limited signal r(τ) near its maximum is even and quadratic to second order, so the YIN valley is parabolic up to a quartic term and the bias is set by that term and the grid position; a Gaussian fit applied to a valley needs a baseline transform and the arXiv authors' own "offset by a constant" step shows how baseline-sensitive it is (derived from the same paper). Second, the PSOLA note argues the 3.76-cent figure is dominated by tracker and response behaviour rather than the read kernel ([Dattorro 1997](https://ccrma.stanford.edu/~dattorro/EffectDesignPart2.pdf) on linear-delay accuracy), and no retrieved source pins the residual on the interpolator; the trial is cheap precisely because that attribution is unknown.

**Proposed trial.** Widen the fine search by one lag on each side (11 lags: +2.0k MACs per hop on the direct code, +128 MACs per block under panes) and fit (a) a 5-point least-squares quadratic and (b) a truncated-sinc fit with S = 2–3 over i = 16 candidate offsets (≈ 10–20 ops per candidate, a few hundred ops per hop). Compare each against the current 3-point parabola on the ctest hard-tune clip and the steady 220 Hz gate; the 1 kHz end of the range is where a difference should appear first. The same choice governs the coarse pass only through the coupling constraint (coarse τ_c error < 1 decimated lag so that T ± 4 brackets the true period), which the current parabola already meets; leave the coarse parabola alone.

## 6. Key equations

YIN difference function and cumulative mean normalised difference ([handoff](00_handoff_current_design.md)):

```
d(τ) = Σ_{j=0}^{W−1} (x[j] − x[j+τ])²
d′(τ) = d(τ) · τ / Σ_{k=1}^{τ} d(k),   d′ = 1 where the sum is 0
δ = ½ (a − c) / (a − 2b + c),  a = d′(τ−1), b = d′(τ), c = d′(τ+1), clamped to ±1, 0 unless a − 2b + c > 0
```

Autocorrelation identity (YIN eq. 7 form, as implemented in pYIN/TarsosDSP, [pYIN YinUtil.cpp](https://code.soundsoftware.ac.uk/hg/pyin/comparison/7cbf40306c10/YinUtil.cpp)):

```
d(τ) = E(0) + E(τ) − 2 r(τ),  E(τ) = Σ_{j=0}^{W−1} x[j+τ]²,  r(τ) = Σ_{j=0}^{W−1} x[j] x[j+τ]
powerTerms[τ] = powerTerms[τ−1] − x[τ−1]² + x[τ+W]²
```

Hildebrand recursive E/H update and periodicity test, eqs. 4–6 ([US 5,973,252](https://patents.google.com/patent/US5973252A/en)):

```
E_i(L) = E_{i−1}(L) + x_i² − x_{i−2L}²
H_i(L) = H_{i−1}(L) + x_i·x_{i−L} − x_{i−L}·x_{i−2L}
E_i(L) − 2H_i(L) ≤ eps·E_i(L)
```

Fixed-W sliding update by h samples (derived; the fixed-window form of the same recursion):

```
d_{t+h}(τ) = d_t(τ) + Σ_{j=W}^{W+h−1} (x[j]−x[j+τ])² − Σ_{j=0}^{h−1} (x[j]−x[j+τ])²
```

Pane decomposition (derived; pane s = the 16 decimated j-values of audio block s, j ∈ [t_s − τ_max − 16, t_s − τ_max)):

```
P_s(τ) = Σ_{j∈pane s} (x[j] − x[j+τ])²        (or  Σ x[j]x[j+τ]  in the autocorrelation form)
d(τ)   = Σ_{s = last 16 panes} P_s(τ)          at the hop boundary
```

Early-late discriminator ([Navipedia DLL](https://gssc.esa.int/navipedia/index.php/Delay_Lock_Loop_(DLL))) and its mapping onto the YIN valley (derived):

```
GPS normalised early-minus-late:  D = ½ (E − L) / (E + L)
Valley form, prompt lag T:        e = ½ (d(T+1) − d(T−1)) / (d(T+1) + d(T−1) − 2 d(T))  ≡ parabola δ with a = d(T−1), b = d(T), c = d(T+1)
Loop:  T ← T + K₁ e   (first order)   or   T ← T + K₁ e + K₂ Σ e   (second order, zero steady-state error on a glide)
```

Catmull-Rom with constant fraction f, precomputed at launch (derived from the handoff's c₁, c₂, c₃ form):

```
h₋₁ = −½f + f² − ½f³
h₀  = 1 − 2.5f² + 1.5f³
h₁  = ½f + 2f² − 1.5f³
h₂  = −½f² + ½f³
y   = h₋₁·x₋₁ + h₀·x₀ + h₁·x₁ + h₂·x₂       (4 mul + 3 add per grain-sample)
```

Praat window rule (derived from the [Praat manual](https://www.fon.hum.uva.nl/praat/manual/overlap-add.html)): L = 2·min(P, P/r); live grains ≤ 2; for r ≥ 1 the Hann sum is 1 and the 1/r gain is unnecessary.

## 7. Limitations and sources not retrieved

The strongest recommendations (panes, predicted-lag fine pass, kernel rewrites) rest on derivations from the handoff's op structure and on documented M7 issue rules, not on a measured M7 implementation; the 1.6–1.75 cycles/MAC VFMA figure and the 0.5–1 cycle/MAC SMLAD figure are issue-slot models and must be confirmed with DWT CYCCNT. No published YIN, autocorrelation or `arm_dot_prod_q15`/`arm_rfft_fast_f32` cycle counts for Cortex-M7 were found (CMSIS-DSP benchmark pages and Teensy forum threads were unreachable; the 55,538-cycle M4 rfft figure is second-hand). The following primary sources could not be read and are cited only through secondary material or from memory: de Cheveigné & Kawahara 2002 (all mirrors refused; eq. 7 corroborated via aubio, TarsosDSP and pYIN); Lent 1989 and Bristow-Johnson 1995 (only the 1993 convention abstract); Moulines & Charpentier 1990; Talkin's RAPT chapter (scan without text) and the G.729 open-loop ranges; Li et al. 2005 "No pane, no gain" (panes construction is the note's own derivation); Sha, Lehoczky & Rajkumar (period transformation) and Liu et al. 1991 (SIAM page blocked); Kaplan & Hegarty's DLL and Tong-detector chapters (counter rules from memory); Jacobsen & Lyons 2003; Céspedes 1995, Zhang & Wu 2005 and Knapp & Carter 1976 (closed-form interpolator bias not quoted); Page 1954; Brown & Puckette 1993 and the fiddle~ ICMC paper; Välimäki & Laakso 2000; the pYIN ICASSP paper; Nehorai 1985; the Arm M7 TRM and ST AN4891/AN4839 on FPSCR.FZ, cache control and lock-down (the M7 L1 has no documented line-lock; TCM placement is the substitute); Hildebrand's Valhalla DSP post was fetched by one pass and Cloudflare-blocked in another; GSnap has no public source; no Antares "low latency" patent could be located because Google Patents rate-limited the assignee query. No listening test or spectral-error figure exists for the Praat window rule applied to pitch raising, no study reports any tracker at ≤ 4 cents RMS on vowels (published comparisons use 10 ms frames and EGG references with jitter of that order, [LYRICS study](https://arxiv.org/pdf/1912.12609)), and no source gives the parabola's bias on a YIN valley; the project's own ctest remains the arbiter for every inexact step.

## Conclusion

The handoff framed the remaining lever as "an FFT-based difference function or a sliding update with spread rebase"; the notes show both are the wrong shape for this problem. The FFT shrinks a burst without moving it, and the sliding update pays for exactness with drift control that the integer-multiple geometry of this design makes unnecessary. Because W is sixteen blocks and the hop is four, the YIN frame decomposes into tumbling sub-windows whose every term is already in the ring when its block arrives; the burst was a scheduling artefact, not a cost of the algorithm. Once the tracker is flat, the engineering question changes from "how many cycles" to "how deterministic": DTCM/ITCM placement and a two-valued per-block cycle distribution are the properties to verify, and the fine fallback becomes the only branch-dependent cost left in the pitch path.

The accuracy question changes too. With cost no longer the constraint, the fine search can afford one more lag on each side and a better interpolator, and the TDE literature says the parabola is the weakest link in that chain. Whether the 3.76-cent figure is interpolator bias or response-smoothing behaviour is unknown and cheap to find out; it should be tested before any further tracker restructuring, because a DLL loop or any other closed-loop refinement would inherit the bias rather than remove it.
